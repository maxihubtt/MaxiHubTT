FARE SYSTEM PROTECTION

This is extremely important.

The Admin and Driver interfaces must NOT create their own fare rules.

There must be ONE source of truth for approved fares.

The system should support:

- 1–12 passengers
- 13–15 passengers
- 16–18 passengers
- 19–25 passengers
- 26+ = custom quote unless specifically configured

Multiple buses:

Approved fare per bus × number of buses.

No automatic multi-bus discount.

Rush fee:

TTD $150 ONCE per booking.

Do NOT charge $150 per bus.

Deposit:

25% of the FINAL TOTAL.

Final total includes applicable rush fee.

Example:

Base fare = $1,000
Rush fee = $150
Final = $1,150
Deposit = $287.50

The frontend and backend must agree exactly.

Never trust a price sent from the browser.

The backend must calculate/validate the authoritative price.

UNKNOWN ROUTES

If there is no approved fare for a route:

DO NOT:

- calculate distance
- estimate price
- use old distance fallback
- round a guessed price
- return $0
- silently choose a nearby route

Instead display:

CUSTOM QUOTE REQUIRED

Then provide:

- Request Quote
- WhatsApp
- Contact MaxiHubTT

The admin should also clearly see that the booking requires a custom quote.

REMOVE/ISOLATE DISTANCE FALLBACK

If the existing system still contains a fallback such as:

straight-line distance × road factor
or
distance × rate
or
automatic rounding

DO NOT use it for customer pricing.

Remove it from the active booking calculation or isolate it so it cannot silently generate customer fares.

Only approved fares should automatically generate prices.
