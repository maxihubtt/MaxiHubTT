IMPORTANT: Core rule

The website must STOP using automatic distance-based fare calculations.

Do NOT use:

- straight-line distance
- road-distance multipliers
- "$25 + distance × $8"
- automatic rounding
- guessed fares
- fallback mathematical formulas
- silently generated prices

A fare must only be displayed if it exists in the approved Maxi Hub TT fare database.

CUSTOM QUOTE REQUIRED

Create ONE master fare configuration/database that contains all approved fares.

The frontend and backend MUST use the same source of truth.

Do not maintain separate frontend and backend fare tables.

The browser may request/display a fare, but the backend MUST independently validate/recalculate the final fare from the master fare configuration before creating a booking.

Never trust a price submitted by the browser.

If the browser sends:

"price: 500"

the backend must ignore that value and calculate the approved price from:

- pickup
- drop-off
- route
- trip type
- passenger count
- number of buses
